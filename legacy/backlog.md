## 1. 「门 + 否决」模式（待实现）

核心：评分前先过硬门，硬门 FAIL 直接否决（不评分、不生成建议），否决优先级高于分数。

国内适配（替换他们面向海外的「公民/永居资格门 + 语言门」）：

| 门 | 国内语义 |
|---|---|
| 应届/社招门 | 岗位明确「仅社招 / 要求 N 年经验」而用户是应届 → 否决 |
| 学历门 | 硬性「统招本科 / 硕士 / 985·211 / 专业对口」，用户不满足 → 否决 |
| 英语门 | 外企/大厂明确「英语可作为工作语言」而用户无对应水平 → 标记或否决 |
| 城市/通勤门 | 岗位城市与用户期望城市不一致 → 否决（或标记，人定夺） |

规则：任何一门 FAIL → 不进投递建议，单独列「已排除 + 原因 + JD 原文佐证」。

## 2. 「两段式粗筛 / 精评」模式（待实现）

现状：`batch` 每个岗位都跑满 4 步（4 次 LLM），成本高。

借鉴 `/rank`（粗筛）与 `/apply`（精评）的分层：

- **粗筛**：只给 JD 原文 + 简历 profile，一次 LLM 出「匹配分 + 硬门槛命中」，便宜，批量跑。
- **精评**：只对进短名单的岗位跑满 4 步（含公司价值观、五段建议、覆盖率）。
- 收益：10 个岗位通常只有 2-3 个值得精评，省约 70% token。
